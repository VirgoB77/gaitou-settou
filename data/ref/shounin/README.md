# 運営者の承認の置き場

**承認できるのは運営者だけ。** 運営者がはっきり承認した中身を、運営者・Codex・Claude などが
このフォルダへ**転記**してよい（2026-09-28）。承認した者は `approved_by`、転記した者は `entered_by` に書く。
**commit した者から、承認した者を推し量らない。** 毎朝の自動実行は、ここには書かない。

取得元の判定カード（`data/ref/torimoto-card.json`）1枚につき、承認のファイル1つ。
ファイル名はカードの名前（例：`kobai-nta-home.json`）。

```json
{
 "カード": "kobai-nta-home",
 "運営者承認": "承認",
 "承認したカード版": 1,
 "承認時カード指紋": "（data/ref/card-ichiran.md に出ている64文字）",
 "承認日": "2026-09-25",
 "approved_by": "operator",
 "entered_by": "codex",
 "approval_source": "（任意。運営者が承認した場所。例：チャット 2026-09-25）"
}
```

## この承認が数えられる条件（`common/kado.py` が毎回確かめる）

- カードの「統括判定案」が「取ってよい」で、必要な欄が全部埋まっている
- 「承認したカード版」と「承認時カード指紋」が、**いまのカード**と一致する
  （承認のあとでカードが1文字でも変わったら、承認は効かなくなる。もう一度承認する）
- `approved_by` が `operator`（**AI・Codex などを承認した者として書いた承認は数えない**）
- `entered_by`（転記した者）が書いてある
- このファイルが保存（commit）されていて、保存したあとで書き換えられていない

どれか1つでも欠けたら、その取得元は「取ってよい」にならず、取りに行かない。

## 門が確かめないこと

**運営者が本当にその中身を承認したかは、門には分からない。** 門が読むのはファイルの中身と、
それが保存されていることだけ。承認を受けてから転記する、という運用の手順で担保する。
承認がどこで出たかは `approval_source` に書いておくと、あとから追える。
